**DOM (Document Object Model)** — это **представление HTML-страницы в виде дерева объектов**, которое браузер создаёт после загрузки страницы.

👉 Проще говоря:  
**DOM-дерево — это то, как браузер “видит” HTML-страницу внутри себя.**

---

# 🧠 Простая метафора

HTML-код — это **текст**  
DOM-дерево — это **структура в памяти браузера**

📘 Метафора:
- HTML → чертёж дома
- DOM → реальный дом с комнатами и этажами
---

# 🌿 Как выглядит DOM-дерево

HTML:
```html
<html>
  <body>
    <h1>Заголовок</h1>
    <p>Текст</p>
  </body>
</html>
```
DOM-дерево:
``` css
document
└── html
    └── body
        ├── h1
        │   └── "Заголовок"
        └── p
            └── "Текст"
```
Каждый тег — это **узел (node)**  
Вложенность тегов = ветки дерева

# 🧩 Основные элементы DOM
- **document** — корень всего дерева
- **element node** — HTML-теги (`div`, `p`, `button`)
- **text node** — текст внутри тегов
- **attribute node** — атрибуты (`id`, `class`, `href`)
# 🔍 Где QA видит DOM-дерево

### В DevTools:
- вкладка **Elements**
- раскрываешь теги как дерево
- видишь реальную структуру страницы

❗ Это **не всегда 1:1 с HTML-файлом**, потому что:
- JS может добавить элементы
- элементы могут быть скрыты
- DOM может меняться динамически

# 🧪 Почему DOM-дерево важно для QA
QA работает **не с HTML-файлом, а с DOM**:
- 🔎 поиск элементов (`id`, `class`, `xpath`, `css selector`)
- 🧪 UI и автотесты
- 🧭 DevTools
- 📱 WebView в мобильных приложениях
- 🧩 JS-ошибки и баги интерфейса

# 🐞 Пример QA-бага, связанного с DOM

> На странице есть кнопка, но её нельзя кликнуть.

Причина:
- кнопка есть в DOM
- но перекрыта другим элементом
- или скрыта CSS

QA это видит **только через DOM**, а не глазами.
